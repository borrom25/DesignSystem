# Правила работы с Git-ссылкой из Figma

## Когда читать этот документ

Читать этот файл, когда пользователь дает макет из Figma, а в Figma-компоненте есть ссылка на Git/репозиторий/исходники компонента.

Главная цель: не верстать компонент заново, а понять, какой готовый компонент уже существует в коде, как его импортировать и какими props собрать нужное состояние.

## Главный принцип

Если в Figma есть ссылка на компонент в Git, эта ссылка является первым источником истины для реализации.

Порядок приоритетов:

1. Импортировать готовый публичный компонент.
2. Настроить его props под Figma variants/states.
3. Собрать композицию из существующих компонентов.
4. Расширить существующий компонент, если API не хватает.
5. Создавать новый компонент или верстать вручную только если готового компонента действительно нет.

Верстать руками то, что уже есть компонентом, запрещено.

## Что делать со ссылкой

Если Figma указывает ссылку на папку компонента:

```text
src/components/Button/
```

читать:

- `src/components/Button/Button.tsx`;
- `src/components/Button/Button.types.ts`;
- `src/components/Button/index.ts`;
- `src/components/Button/styles`;
- `src/stories/Button.stories.tsx`;
- `src/index.ts`, чтобы понять публичный export.

Если Figma указывает ссылку на конкретный файл:

- на `<Component>.tsx` - читать runtime и рядом лежащие `types`, `styles`, `index`;
- на `<Component>.types.ts` - использовать как источник публичного API;
- на story - использовать как источник примеров состояний, но все равно найти runtime component.

Если ссылка ведет на GitHub/GitLab web URL, сопоставить ее с локальным путем в проекте. Не работать по памяти: открыть локальный файл.

## Как понять, что импортировать

1. Найти локальный `index.ts` компонента.
2. Проверить, что компонент экспортируется из `src/index.ts` или другого публичного barrel.
3. Использовать публичный импорт пакета, а не внутренний путь, если код находится вне самой библиотеки.
4. Внутри библиотеки повторять локальные import-паттерны соседних компонентов.

Для внешнего usage/snippet предпочитать:

```ts
import { Button } from "kit";
```

Для внутренней реализации внутри библиотеки ориентироваться на существующие импорты соседних компонентов.

Не импортировать из `dist`.

## Как использовать компонент

После чтения `*.types.ts` и story составить mapping:

- Figma variant -> prop;
- Figma state -> prop или runtime state;
- Figma boolean property -> boolean prop;
- Figma text layer/property -> `children`, `label`, `title`, `placeholder` или другой существующий prop;
- Figma icon slot -> icon prop, `LucideIcon`, `ReactNode` или существующий slot prop;
- Figma nested component -> импорт существующего компонента и композиция.

Если нужное состояние уже есть в story, повторить этот usage.

Если в Figma есть несколько вложенных компонентов со своими Git-ссылками, обработать каждую ссылку отдельно и собрать экран композицией готовых компонентов.

## Когда можно менять компонент

Расширять существующий компонент можно, если:

- Figma показывает реальный variant/state, которого нет в API;
- новое поведение системное и подходит компоненту;
- изменение совместимо с существующими props;
- обновлены types, styles и story.

Перед расширением компонента проверить похожие components и shared helpers.

## Когда можно верстать вручную

Ручная верстка допустима только для:

- layout-контейнера, который не является компонентом дизайн-системы;
- временной обертки вокруг импортированных компонентов;
- уникального screen-level расположения;
- отсутствующего компонента после проверки `src/components`, stories и Git-ссылок.

Даже в этих случаях сначала использовать существующие tokens, styles и shared utilities.

## Если ссылка битая или компонента нет локально

1. Проверить, не переименован ли компонент.
2. Найти похожие компоненты через `rg`.
3. Проверить `src/index.ts`, `src/components/index.ts`, `src/stories`.
4. Сообщить пользователю, что Git-ссылка не совпадает с локальной структурой.
5. Только после этого выбирать: использовать ближайший компонент, расширить его или создать новый.

## Что фиксировать в ответе пользователю

Когда работаешь по Figma Git-ссылке, в итоговом ответе кратко указать:

- какую ссылку/папку из Figma использовал;
- какой компонент импортировал;
- какие props сопоставил с Figma variants/states;
- если пришлось верстать вручную, почему нельзя было импортировать готовый компонент.

## Запрещено

- Верстать с нуля компонент, на который Figma дала Git-ссылку.
- Игнорировать `*.types.ts`.
- Импортировать из `dist`.
- Создавать дубликат существующего компонента.
- Использовать внутренний путь вместо публичного импорта там, где нужен внешний usage.
- Молча менять API компонента.
- Молча заменять Figma variant ближайшим prop без `assumption` или пояснения.
