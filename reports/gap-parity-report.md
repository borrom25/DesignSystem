# Gap Parity Report: node `22261:7814`

## Что было не так

- В реализации был потерян один критический вертикальный `gap`, который в макете равен `40px`.
- В коде это место было задано как `gap-10`.
- По токенам проекта `gap-10 = --generic-spacing-10 = 22px`, поэтому блоки оказались визуально ближе друг к другу, чем в Figma.

## Где исправлено

- Файл: `src/App.tsx`
- Было: `gap-10`
- Стало: `gap-15`
- По токенам проекта `gap-15 = --generic-spacing-15 = 40px`, что соответствует целевому зазору в макете.

## Почему это произошло

- На этапе первой сборки часть page-level spacing была выставлена из общего визуального приближения, а не из таблицы контрольных размеров по нодам.
- Конкретный `gap` попал не в тот шаг spacing-scale: `10` вместо `15`.
- Это не ошибка DS-компонента. Это ошибка page-level композиции и выбора token-step.

## Как упреждать

Перед версткой каждого экрана нужно делать короткую geometry map по ключевым узлам:

- width основного контейнера;
- высота header/content-блоков;
- вертикальные и горизонтальные gap между основными секциями;
- padding основных контейнеров;
- расстояние `PageHeader -> next section` на desktop.

Для каждого такого значения сразу фиксировать связку:

```text
figma px -> token variable -> tailwind/class
```

Пример:

```text
40px -> --generic-spacing-15 -> gap-15
22px -> --generic-spacing-10 -> gap-10
```

Перед сдачей нужен отдельный checkpoint:

```text
Critical spacing parity check
```

На этом checkpoint проверяются только ключевые gap/offset без остального визуального шума.
